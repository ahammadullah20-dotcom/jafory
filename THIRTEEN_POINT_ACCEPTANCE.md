## Published-release diagnosis and corrective change

The owner’s Netlify screenshot confirms that `main@a6b6c78` was already **Published** from GitHub, so the previous symptom was not caused by an unuploaded ZIP or a pending deployment. Live runtime tracing showed the deployed bundle already contained the visible admin fallback strings; anonymous `/api/trpc/auth.me` returned `200` with `null`, anonymous `/api/trpc/admin.overview` returned `403 FORBIDDEN`, and public `catalog.home` returned `200`. The remaining flow defect was in the sign-in intent: the admin Sign in button sent every Supabase magic link to `/account`, while `/account` had no callback handoff to `/admin`.

The corrective source now sends admin-originated magic links to `/account?next=%2Fadmin` and safely redirects an authenticated admin from that callback page to `/admin`; normal public sign-in remains on `/account`, and non-admin accounts are not redirected. The fix passes TypeScript, **45 Vitest tests** with 5 legacy tests intentionally skipped, production build, Netlify Function build, and a fresh 7,369,142-byte ZIP integrity/marker check with 94 media files. This corrective ZIP has **not** been pushed to GitHub or Netlify yet; one new publish requires owner approval because the current live release is already published.
